# Architecture — Phase 2 contract/security boundary

`services/agent-gateway` contains the copied Codex bridge, Gemini/OpenRouter adapters, MCP Host, and internal HTTP runtime. `packages/contracts/agent.v1.json` owns generic runtime, event, egress, and sandbox-only approval envelopes. `agent_security.ts` enforces generic owner/turn/digest/expiry approval binding in the Codex bridge and defines context-egress consent checks for later consumers. These checks do not grant Janus domain operations.

Janus owns `janus-context.v1.json`, source authorization, PIT/as-of, provenance, sanitization, canonical facts, the approval deny policy, investment auth, investment User/Admin UI, and the currently deployed legacy Chat/API/gateway. The Janus `assistant.v1.json` and `engine_security.py` remain live compatibility implementations; no service imports this repo's source at runtime. `JanusContextClient` is the isolated authenticated bounded HTTP consumer; it is not wired into live turn routing. It never reads Janus PostgreSQL, GCS, Iceberg, or internal packages. No Chat storage cutover or cross-project live integration is claimed.

`services/chat-api` and `omni_chat` define omniAgent's independent Chat API and future durable write ownership. Google subject, not email, keys its owner map; internal event writes use an allowlisted service identity. The current API can queue messages, replay stored events, and record approval decisions. The new schema is not applied and no runtime traffic is routed to it; Janus remains the live chat writer until the [migration gate](chat-storage-migration.md) is met.

`apps/agent_app` now owns the generic Flutter Chat surface and talks only to omniAgent's Chat API. The Janus source no longer contains ChatPage/Ask Janus navigation; its deployed UI is unchanged until a separate cutover. Tool/Skill management and Janus context selection are visibly pending, not routed to legacy Janus endpoints. See [UI ownership](ui.md).
